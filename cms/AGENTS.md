# cms — 관리 도구

## 이 덩어리가 맡는 것

게시판 글·페이지·메뉴의 저장소. 컬렉션 구조, 역할과 권한, 예약 게시,
다국어, 관리자 IAM 로그인 다리, 백엔드가 쓸 서비스 계정.

## 맡지 않는 것

- **공개 화면을 모른다.** `web`·`api` 의 코드를 읽지 않는다.
- 브라우저가 여기를 직접 부르지 않는다. 백엔드가 대신 읽는다.
- 메일 발송·문의 속도 제한은 `api` 것이다.

## 늘 지켜야 하는 것

- **구조를 손으로 만들지 않는다.** `scripts/schema.py` → `roles.py` →
  `seed.py` 순서로 만든다. 순서를 바꾸면 쓸 곳이 없는 상태에서 쓰게 된다.
  관리 화면에서 눌러 만든 것은 다음 사람이 재현하지 못한다.
- **서비스 토큰은 한 번만 찍힌다.** `scripts/service_account.py` 가 발급하고
  다시 보여 주지 않는다. 저장소에 넣지 않는다.
- **토큰 회전은 무중단이 아니다.** 발급 → 환경변수 교체 → 백엔드 재시작
  순서를 지킨다. 어기면 그 사이 요청이 전부 실패한다.
- **IAM 다리를 켠 뒤에는 `scripts/iam_bridge_sync.py` 를 반드시 한 번
  돌린다.** 로컬에서는 `marketing@` 에 매핑한다 — admin 을 돌리면 스모크가 못 들어간다. Directus Core 는 로컬 로그인 창을 못 끈다. 다리는 문을 하나 더
  만들 뿐이라, 계정 비밀번호를 사람이 모르는 파생값으로 바꿔야 IAM 이 유일한
  입구가 된다.
- **비밀번호를 어디에도 적지 않는다.** 서명 키에서 정해진 방식으로 만들어
  낸다. 환경변수에도 설정 파일에도 비밀번호 자체가 없다.
- 계정 자리(seat)가 3명이다. 등록할 수 있는 사람도 최대 3명이고, 목록에
  없는 사람은 거부된다.
- **표본 데이터는 초안 상태로 둔다.** 공개 상태로 두면 사이트에 시연용 글이
  뜬다.

## 이 덩어리의 방식

- Directus Core 는 SSO 가 라이선스로 막혀 있다(`sso_enabled` is a restricted
  resource). 그래서 확장으로 우회한다 — 이 제약을 모르면 왜 확장이 있는지
  알 수 없다.
- 게시판은 컬렉션 하나에 종류를 고르는 칸을 둔 구조다. 종류마다 컬렉션을
  만들지 않는다.
- 표시 날짜(`published_date`)와 예약 시각(`publish_at`)은 다른 것이다.
  앞은 사람이 보는 날짜, 뒤는 언제 공개할지를 정하는 장치다. 화면의 기간
  검색은 앞을 기준으로 한다.

## 무엇을 검사하나

```bash
bash scripts/smoke.sh              # 112/112 (IAM 다리 3항 포함)
```

`smoke.sh` 는 연속 두 번 돌려도 데이터가 안 쌓여야 한다. 뒷정리 검사가
제대로 도는지는 **뒷정리를 꺼서** 확인한다 — 끄면 실패가 나와야 한다.
안 나오면 그 검사는 아무것도 안 보고 있는 것이다.

**Directus 는 모르는 필드를 조용히 버린다.** 기본값이 있는 필드면 오류도
안 난다. 그래서 「저장됐다」가 아니라 **「값이 맞다」** 로 검사한다.
