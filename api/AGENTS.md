# api — 백엔드

## 이 덩어리가 맡는 것

공개 화면이 부르는 HTTP 전부. 게시판 읽기, 문의 접수와 메일 발송,
옛 게시판 경로(관리자 로그인·채팅), 관리자 세션, IP 별 속도 제한.

## 맡지 않는 것

- **화면을 그리지 않는다.** HTML 을 내보내지 않는다.
- 게시판 글의 내용 모델을 정하지 않는다. 그건 `cms` 것이다.
- 사람을 인증하지 않는다 — 사람 로그인은 사내 IAM 과 `cms` 의 다리가 한다.
  여기서 하는 것은 **요청**이 게이트웨이를 거쳤는지 보는 것이다.

## 늘 지켜야 하는 것

- **빠뜨리면 닫힌다.** `SESSION_SECRET` 이나 (검증이 켜진 상태의)
  `IAM_GATEWAY_SECRET` 이 없으면 **서버가 안 뜬다.**
  `IAM_ENFORCE_GATEWAY` 와 `SESSION_SECURE` 는 값이 없으면 **켠 것으로 본다.**
  이 방향을 뒤집는 변경은 하지 않는다.
- **새 컨트롤러는 기본이 게이트웨이 뒤다.** `@SkipGatewaySignature()` 를
  붙이지 않으면 자동으로 서명을 요구한다. 공개 화면이 직접 부르는 셋
  (content · inquiry · notify)에만 붙어 있다. 새로 붙일 때는 그 경로가
  정말 익명 공개여야 하는지 먼저 판단한다.
- **`page/support/notice_api.php` 와 `notice_login_callback.php` 의 주소를
  바꾸지 않는다.** IAM 화이트리스트에 글자 그대로 등록돼 있다.
  `setGlobalPrefix` 의 예외 목록이 그것이다.
- **옛 게시판 쓰기(`create`·`update`·`delete`)는 `410` 으로 닫힌 채 둔다.**
  살리면 성공 응답을 받으면서 사이트에는 안 나오는 글이 생긴다.
- **문의 칸 이름과 길이 한도를 좁히지 않는다.** 이름 200 · 연락처 50 ·
  내용 5000. 좁히면 지금 PHP 로는 들어가던 문의가 거절된다.
- **저장 성공을 「200 이 왔다」로 판정하지 않는다.** Directus 는 모르는
  필드를 조용히 버린다. 행이 생겼고 값이 원문 그대로인지까지 본다.
- **`TRUST_PROXY` 는 숫자로 넘긴다.** 문자열 `"1"` 은 IP `0.0.0.1` 하나를
  믿는 목록으로 읽혀 결과적으로 아무것도 안 믿는다.
- **토큰을 로그에 찍지 않는다.** 진단이 필요하면 서버 로그에 위치만 남긴다.
  주소창 쿼리에 실어 보내는 코드는 원본에 있었지만 옮기지 않았다.

## 이 덩어리의 방식

- 관리자 세션 쿠키 이름은 기본이 `DVADMINSID` 다(`NOTIFY_SESSION_NAME` 으로
  바꿀 수 있다). PHP 는 `PHPSESSID` 를 쓰기도 했다 — 옛 이름으로 찾으면
  안 나온다.
- **세션은 파일**이다(`NOTIFY_STATE_DIR/sessions`). 배포해도 로그인이 안
  풀리고, 컨테이너를 늘리면 그 폴더를 공유하면 된다. **속도 제한과 채팅
  토큰만 프로세스 메모리**다 — 늘리는 순간 IP 당 한도가 프로세스당 한도가
  되므로 그때는 공유 저장소가 필요하다. 둘의 대응이 다르다.
- Directus 이름을 **그대로** 내보낸다. 옛 게이트웨이는 `isPinned`·
  `createdAt` 을 썼지만 지금 API 도 화면도 `is_pinned`·`published_date`
  로 주고받는다. 변환하는 코드는 없다.

## 무엇을 검사하나

```bash
bash scripts/verify.sh          # 55/55
bash scripts/verify-notify.sh   # 37/37  (가짜 게이트웨이를 세운다)
npm run typecheck
```

문의 구간은 **1분 안에 두 번 돌리면 속도 제한에 걸려 판정 불가**로 빠진다.
통과도 실패도 아니다. 속도 제한 자체를 재려면 `RL_CHECK=1` 을 준다.

검사는 응답만 보지 않는다 — **우리가 무엇을 보냈는지**까지 본다.
서버가 값을 강제하는지, 보내지 말아야 할 필드를 빼는지는 요청을 봐야 안다.

돌연변이로 검사의 유효성을 확인한다. 예: `TRUST_PROXY` 변환을 되돌리면
IP 별 한도가 하나로 합쳐지는 것이 잡혀야 한다. 안 잡히면 그 검사는 아무것도
안 보고 있는 것이다.
