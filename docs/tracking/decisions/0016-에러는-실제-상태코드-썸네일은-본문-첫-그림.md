# 0016 · 에러는 실제 HTTP 상태로 낸다 · 글 목록 썸네일은 본문의 첫 그림이다

## 왜 정해야 했나

둘 다 bmes 를 따르거나 따로 칸을 두는 쪽으로 갈 수도 있었다.

1. bmes 의 `CommonExceptionFilter` 는 에러도 **HTTP 200** 에 본문(`status`·`resultCode`)만 바꿔 낸다.
   이 저장소는 에러 본문 모양을 bmes 에 맞추면서(`{ data: null, status, resultCode, message }`) 상태
   코드를 어떻게 할지 정해야 했다.
2. 글 폼에 「대표 이미지」 올리기 칸이 오른쪽 설정에 따로 있었다. 사용자: 사진은 본문에 넣는 것이다.

## 무엇을 골랐나

1. **실제 HTTP 상태**(400·401·403·404·409·413·429·5xx). 본문 모양만 bmes 와 같다.
   관리 화면의 401 → 로그인 이동(`adminFetch`), 공개 문의 폼의 429 분기, 속도 제한 약속
   (`docs/contracts.md`), verify.sh 의 상태 코드 검사가 전부 상태 코드에 기댄다. 브라우저·프록시·
   캐시도 상태 코드를 본다.
2. 공지·보도·뉴스의 `thumbnail` 은 **api 가 저장할 때 본문의 첫 그림**(`/api/content/assets/<uuid>`,
   한국어 본문 먼저)으로 정한다. 보낸 `thumbnail` 은 보지 않는다. 본문에 그림이 없으면 비운다.
   증서(특허·저작권)는 그림이 곧 글이라 `thumbnail` 을 직접 받는다 — 본문 칸 자리에 둔다.

## 안 고른 것

- **bmes 처럼 200** — 위의 기대들을 전부 본문 검사로 바꿔야 하고, 실패가 캐시·로그에서 성공으로 보인다.
- **썸네일을 본문 그림 중에서 고르는 칸** — 지금은 없다. 필요해지면 본문 그림 목록에서 고르게 하고,
  api 는 「고른 값이 본문에 있으면 그것, 없으면 첫 그림」으로 바꾼다.

## 그래서 생긴 제약

- bmes 쪽 공용 클라이언트(200 을 기대하는 것)를 이 api 에 그대로 붙일 수 없다.
- 폼의 썸네일 미리 보기(`PostForm.tsx`)는 api 규칙을 흉내 낸다. 규칙을 바꾸면 둘 다 고친다.
- 지금까지 올라간 공지·보도에는 대표 이미지가 없었다(0건) — 바꾸면서 사라진 썸네일은 없다.
