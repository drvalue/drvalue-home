# 0012 · 옛 게시판 API 와 관리자 세션을 지운다

## 왜 정해야 했나

PHP 서버를 버리고 새 서버로 간다. 이관하면서 옮긴 것 중 지금 아무도 안
부르는 것이 남아 있었다.

## 무엇을 골랐나

- `page/support/notice_api.php` · `notice_login_callback.php` 를 Nest 에서
  지운다. 게시판 읽기는 `/api/content/posts`(Directus) 로 갔고, 관리자
  로그인 단추는 화면에서 이미 빠졌고, `chat_resolve` 는 그 로그인이 만드는
  sid 에만 의존했다. `web/` 에서 부르는 곳이 없다.
- express-session · 파일 세션 · `SESSION_*` · `NOTIFY_*` · `/data` 볼륨도
  같이 지운다.
- `/api/content/pages` · `/api/content/menu` 도 지운다. 메뉴는
  `web/lib/menu.ts`, 페이지는 React 다. CMS 의 컬렉션은 그대로 둔다.
- api 코드 모양은 `drvalue-bmes-backend` 를 따른다:
  `app/` · `core/<기능>/{controller,service,dto,error}` · `common/`(공용
  인프라) · 컨트롤러는 서비스만 주입 · 에러는 코드 객체.

## 안 고른 것

- **`.php` 두 경로를 남긴다** (0004) — IAM 화이트리스트 때문에 남겼는데,
  로그인 흐름이 없어졌으니 지킬 것이 없다.
- **IamModule 도 뺀다** — 지금 지키는 경로는 0개지만, 「새 컨트롤러는 기본이
  게이트웨이 뒤」 정책은 유지한다. 빼는 것은 정책 변경이라 따로 정한다.

## 그래서 생긴 제약

- 옛 `.php` 두 주소는 404 다.
- `verify.sh` 는 55 → 46 이다. 기능과 함께 검사를 뺀 것이지 회귀가 아니다.
- 배포 워크플로가 만드는 `notice_config.php` 는 PHP 를 버릴 때 같이 뺀다.
