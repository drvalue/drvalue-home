# 0021 · 자동 글 묶음을 토큰 입구(HTTP)로 받는다

## 왜 정해야 했나

2026-11-13 구조가 「글은 사람 기계의 에이전트가 쓰고, 판정과 그림은 ChatGPT 웹이 맡는다」로 바뀌었다. 모델을 부르는 일이
전부 사람 기계에서 끝나 Claude API 요금이 들지 않는다. 남은 것은 그렇게 만든 묶음을 운영 DB 에 넣는 길이었다.
있던 길은 서버 안에서 도는 명령(`docker exec … --publish-bundle`)뿐이라, 예약 실행이 쓰려면 맥에서 서버로 가는 SSH 가
정해져야 했다 — 정해진 적이 없다.

2026-11-16 사용자가 「받는 API 를 새로 만들어 그걸로 제출하게」 하기로 정했다.

이 저장소에는 「IAM 을 안 거치는 문은 없다 — 토큰·헤더 우회 경로 금지」(`docs/standards.md`)와, 결정 0020 의
「바깥에서 글을 쓰는 인증 길을 열지 않는다」가 있다. 이 결정은 그 둘에 **예외 하나**를 낸다.

## 무엇을 골랐나

- **`/api/autopost/*` 두 주소를 연다.** `POST /api/autopost/bundle`(묶음을 공개) · `GET /api/autopost/rules`
  (쓰는 쪽이 읽는 규칙과 「이미 다룬 글」 — 운영 기록으로).
- **문은 토큰이다**(`Authorization: Bearer`, 서버 `.env` 의 `AUTOPOST_SUBMIT_TOKEN`). 부르는 쪽이 사람이 아니라 예약
  실행이라 IAM 로그인을 거칠 수 없다. **관리 화면의 문은 그대로다** — `/api/admin/*` 는 여전히 `Authorization` 을 안 본다.
  이 토큰으로는 글 하나를 뉴스 게시판에 넣는 것만 된다(고치기·지우기·다른 게시판·문의 읽기는 안 된다).
- **빠뜨리면 닫힌다.** 토큰이 비었거나 모양이 틀리면(32자 미만 등) 두 주소 모두 무엇을 보내도 401 이다.
- **서버는 판정을 다시 하지 않는다.** 브라우저가 없다. 코드 검사(구조·숫자·금지 이름·이미 낸 출처)는 운영 기록으로 다시 돌리고,
  cron 과 같은 주간 기록을 잡고 닫는다 — 한 주에 한 편.
- 묶음 공개에 켜기 값(`AUTOPOST_ENABLED=1`)을 따로 요구하지 않는다. 토큰을 넣은 것이 켠 것이다. 토큰만으로는 cron(서버가 직접
  쓰는 길)이 켜지지 않는다.
- 익명 요청의 본문은 전역 한도(100KB)까지만 읽는다. 토큰이 맞는 요청만 9MB 까지 읽는다(앞의 web 프록시가 10MB 에서 자른다). 속도 제한(IP 당 분 5 · 시 30)을
  토큰 검사보다 먼저 건다.

## 안 고른 것

- **SSH 로 묶음을 올리고 `docker exec`** — 새 입구가 없어 공격면이 안 는다. 사용자가 API 쪽을 골랐다. 그 길(`--publish-bundle`)은
  그대로 남아 있다.
- **관리 API 에 서비스 계정** — 관리 화면의 문 자체에 우회로가 생긴다. 이 토큰이 할 수 있는 일을 「자동 글 한 편 넣기」로
  좁혀 두려고 주소를 따로 냈다.
- **묶음에 서명(HMAC)** — 전송 중 변조는 TLS 가 막고, 토큰이 새면 서명 키도 같은 자리에서 샌다. 얻는 것이 없다.
- **서버에서 판정 다시 하기** — 운영 서버에 브라우저·로그인이나 유료 API 키가 있어야 한다. 구조를 바꾼 이유가 사라진다.

## 대가

- **토큰이 새면 누구나 회사 이름으로 글을 공개한다.** 사람 검수도 판정도 없다. 남는 벽은 코드 검사뿐이다 — 숫자마다 주장이
  있고 금지 이름이 없으면 지난다. 주장의 출처가 실제로 그 말을 하는지는 서버가 보지 않는다. 한 주에 한 편이라는 한도가 피해의
  크기를 정한다(그 주의 글이 이미 있으면 못 넣는다 — 반대로 **공격자가 먼저 넣으면 진짜 글이 그 주에 못 나간다**).
- 토큰은 두 곳에 있다: 서버 `.env` 와 사람 기계의 `.env`. 사람 기계 쪽이 더 약하다.
- 토큰이 틀린 채 그림이 든 묶음을 보내면 401 이 아니라 413 이 돌아온다(큰 본문을 안 읽어서). 보내는 명령이 그렇게 풀어서 알린다.
- 바꾸려면 서버 `.env` 를 고치고 api 를 다시 띄운다. 폐기 목록이 없다 — 값 하나가 전부다.
- 실패 알림이 여전히 없다. 예약 실행이 조용히 실패하면 `autopost_runs` 를 보기 전에는 모른다.
