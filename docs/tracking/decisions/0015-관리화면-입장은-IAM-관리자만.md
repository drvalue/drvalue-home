# 0015 · 관리 화면에는 IAM 관리자만 들어온다 — admin_users 는 그 판정의 거울

## 왜 정해야 했나

IAM 계정에는 일반 사용자도 있다. 처음 만든 판정(IAM 그룹 · nxcms root · 「표가 비면 첫 로그인자를
관리자로」)은 누가 관리자인지를 우리가 추측하는 구조였다. 사용자 결정: **관리자는 IAM 이 지정하고,
IAM 관리자가 아니면 접속 자체가 안 된다. 우리는 그 판정을 받아 동기화한다.**

## 무엇을 골랐나

- 입장 = IAM 토큰 `role === 'PLATFORM_ADMIN'`. 토큰은 서버가 code 를 IAM 에 직접 교환해 받은
  것이라 위조 경로가 없다. 그 밖의 IAM 계정은 우리 표에 무엇이 있든 403.
- 동기화 = 로그인할 때마다 `admin_users` 에 받아 적는다. IAM 관리자면 행을 만들거나 갱신
  (enabled=true · 이름 · iam_sub · last_login_on). 관리자가 아니게 된 사람이 로그인을 시도하면
  그 행을 끈다. 가드는 60초마다 행을 다시 본다 — 꺼진 행은 세션이 남아 있어도 막힌다.
- `admin_users.role` 은 입장을 주지 않는다. IAM 관리자들 사이에서 **고칠 수 있는 범위**만 나눈다
  (admin 전부 · marketing 채용 빼고 · hr 채용만). 처음 들어오면 admin.
- nxcms(M.AX) root 판정 · IAM 그룹 판정 · 첫 로그인 자동 등록은 뺐다.

## 안 고른 것

- **IAM 내부 API 로 주기적으로 IAM 을 묻는다** — 자격(내부 API 키)을 쓰지 않기로 했다(Doppler 안 씀).
  그래서 IAM 에서 관리자를 해제해도 **그 사람이 다시 로그인을 시도하거나 세션(30분)이 끝날 때까지**
  남은 세션은 산다. 곧바로 끊어야 하면 CMS 「권한」에서 범위를 줄이거나, 이 결정을 다시 연다.
- **CMS 에서 사람을 추가한다** — 입장을 CMS 가 주게 된다. IAM 이 원본이라는 결정과 맞지 않는다.

## 그래서 생긴 제약

- IAM 이 PLATFORM_ADMIN 을 주지 않으면 아무도 못 들어온다(복구: IAM 에서 지정).
- 마지막 admin 범위를 marketing/hr 로 내리면 409 — 스스로 잠그지 않게.
- 검사(verify.sh)는 서명 키로 세션을 만들고 검사 계정을 표에 잠시 넣는다(IAM 로그인의 동기화를 흉내).
  서버에는 IAM 을 안 거치는 입구가 없다.
