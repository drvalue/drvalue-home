# 0020 · 제조 AI 주간 글을 사람 검수 없이 공개한다

## 왜 정해야 했나

2026-11-12 사용자가 회사 사이트에 제조 AI 소식을 풀어 쓴 글을 자동으로 올리기로 했다. 기준은 Threads `@choi.openai` 의
형식(훅 + 번호 단락 + 출처)이고, 소재를 제조 AI 로 좁힌다. 같은 사용자의 다른 서비스(fitbory)는 「조사 → 집필 → 검사 →
검수 대기 → 사람이 승인」으로 돌린다. 여기서는 승인 단계를 둘지가 갈림이었다.

이 저장소에는 「쓰기는 관리 화면에서만」과 「화면에 쓰는 글은 지어내지 않는다」(`docs/business-rules.md`)가 있다.
자동 글은 둘 다에 걸린다.

## 무엇을 골랐나

- **주 1회, 검사를 통과하면 승인 없이 바로 공개한다.** 사용자가 정했다 — 「검수를 안 하고 그냥 승인할 것」이라 승인 단추는
  아무것도 막지 못한다.
- 사람 검수의 자리를 **자동 검사**가 맡는다. 본문의 숫자는 전부 주장 목록에 있어야 하고, 글을 쓴 호출과 다른 호출이 출처
  원문을 다시 읽어 주장마다 확인한다. 출처는 발행 14일 안, 이미 낸 글의 출처와 겹치면 안 된다.
- **떨어진 글은 게시판에 두지 않는다.** 초안으로 두면 관리 화면에서 한 번 눌러 공개된다. 기록 표(`autopost_runs`)에만 남기고
  그 주는 건너뛴다.
- **회사·제품에 대한 문장은 모델이 쓰지 않는다.** 이름이 나오면 떨어진다. 글 끝의 문의 문구는 코드 상수다.
- **바깥에서 글을 쓰는 인증 길을 열지 않는다.** api 안의 cron 이 글 서비스의 시스템 행위자 입구(`createAsSystem`, 뉴스에만)를
  부른다. 새 비밀값은 Claude API 키 하나이고, 빠뜨리면 꺼진다.
- AI 작성 표기는 넣지 않는다(사용자 결정). 법적 의무 여부는 확인하지 않았다.
- 정해진 시각에 한 번 쏘지 않고 한 시간마다 「이번 주 글이 있나」를 본다 — 배포는 사람이 서버에서 직접 하고, 그 순간 내려가
  있으면 그 주를 놓친다.

## 안 고른 것

- **초안으로 쌓고 사람이 승인** — 틀린 글이 나갈 위험이 가장 작다. 사용자가 읽지 않고 승인하겠다고 해서 뺐다. 되돌리기는
  쉽다: `autopost-default.service.ts` 의 저장 상태를 `draft` 로 바꾸면 된다.
- **GitHub Actions 나 바깥 스케줄러가 관리 API 를 부르기** — 서비스 토큰 인증이 새로 필요하다. 「IAM 을 안 거치는 문은
  없다」를 깬다.
- **출처를 api 가 직접 열어 대조** — 모델이 고른 주소를 서버가 여는 면(SSRF)이 생긴다. Anthropic 쪽 fetch 도구에 맡겼다.
- **실패 알림(디스코드 등)** — 사용자가 방식을 정하지 않았다. 지금은 로그와 기록 표뿐이다.

## 대가

- **검사가 못 막는 것이 그대로 회사 이름으로 나간다**: 출처 자체가 틀렸거나 과장된 보도자료 · 수치는 맞는데 해석이나 전망이
  과한 문장 · 판정 호출이 틀리게 「있다」고 한 경우 · 중요하지 않은 소식을 고르는 것.
- **코드가 보장하는 것과 모델 판정에 기대는 것이 다르다.** 코드: 본문 숫자마다 그 문단에 주장이 있다 · 주장의 출처가
  실제로 열렸다(도구 결과) · 한글로 푼 수량이 없다 · 금지 이름이 없다 · 출처가 조사가 찾은 주소 안에 있다.
  모델 판정: 그 숫자가 원문에서 그 뜻으로 쓰였나 · 같은 문단 안 다른 문장의 같은 숫자 · **숫자가 없는 주장(인용한 말,
  누가 무엇을 발표·계약·도입했다)** · 출처 발행일과 본문 날짜. 뒤쪽은 판정 호출 하나가 틀리면 그대로 나간다.
- 금지 이름은 목록과 변형(띄어쓰기·음차·전각)을 본다. 목록에 없는 제품 이름(GrowTalk·everyrag·CADON 등)과 에두른
  지칭은 못 막는다. 「M.AX 얼라이언스」가 든 문장은 무엇이든 이름 검사를 지난다.
- 몇 주째 글이 건너뛰어져도 누가 `autopost_runs` 나 로그를 보기 전에는 모른다.
- Claude API 요금이 든다. 한 편당 비용은 **NA**(2026-11-12 현재 실제 실행을 못 했다 — 이 환경에 키가 없었다).
- 2026-11-12 현재 실제 Claude 호출로는 한 번도 돌려 보지 못했다. 순서·검사·저장은 가짜 호출과 실제 DB 로 확인했다.
  운영에서 켜기 전에 `npm run autopost -- --preview` 로 몇 편을 읽어 본다.

## 2026-11-13 덧붙임 — 모델을 ChatGPT 웹으로도 부른다

Claude API 로 다섯 편을 돌려(약 $13) 한 편도 통과하지 못한 뒤, 사용자가 「웹 지피티를 ego 브라우저로 쓰자」고 정했다.
`AUTOPOST_PROVIDER=webgpt` 면 사람 기계의 ego 브라우저로 chatgpt.com 을 조작해 조사·집필·판정을 한다. 지시문·검사·판정
기준은 그대로이고 모델을 부르는 길만 바뀐다(Claude API 길은 남아 있다).

- **위 「안 고른 것」 하나를 이 길에서는 고른다**: 출처를 코드가 직접 연다. 웹 화면은 모델이 무엇을 열었는지 알려 주지
  않아서 「열린 출처」를 도구 결과로 셀 수 없다. 코드가 쿠키 없이 바깥 https 주소만 열어 받은 글자를 판정에 붙인다 —
  「모델이 읽었다고 한다」보다 센 보증이다. 대신 모델이 고른 주소를 이 기계가 연다. 운영 서버에서는 켜지 않는다.
- **서버에서 못 돈다.** api 컨테이너에는 브라우저도 로그인도 없다. 사람 기계가 켜져 있고 ChatGPT 에 로그인돼 있어야 한다.
  사람 기계에서 만든 글을 운영 DB 로 보내는 길은 **아직 없다**(새 쓰기 통로라 따로 정한다).
- **화면에 기댄다.** 입력창·「소리 내어 읽기」 단추 같은 이름표로 답이 끝났는지 본다. chatgpt.com 이 바뀌면 깨지고,
  그 실행은 오류로 닫힌다(글이 나가는 쪽으로 깨지지 않는다).
- **판정의 독립성이 약해진다.** 일반 채팅은 그 계정의 메모리·맞춤 지침을 타고, 어느 모델이 답했는지 코드가 모른다.
  집필과 판정이 같은 계정의 서로 다른 새 채팅이라는 것까지만 보장한다.
- 화면을 프로그램으로 조작하는 것이 OpenAI 이용 약관에 맞는지는 확인하지 않았다(사용자 결정).
- 요금은 구독에 든다 — 편당 추가 비용이 없다. 토큰 수는 기록되지 않는다(0).
- **판정 기준을 한 곳 넓혔다(두 길 모두)**: 「머신비전은 카메라 영상을 컴퓨터가 분석하는 방식입니다」 같은 일반 용어
  풀이 문단은 출처에 없어도, 출처와 어긋나지 않고 사실(누가·수치)이 섞이지 않았으면 통과다. 말투 규칙이 어려운 개념을
  풀어 쓰라고 하는데 판정이 그 문단을 전부 떨어뜨렸다(ChatGPT 웹 첫 글). 대가: 용어 풀이가 틀려도 검사가 못 잡는다.
- **그림을 붙인다(ChatGPT 웹 길만, 2026-11-13 사용자 요청)**: 검사를 통과한 글에 한해 그림마다 새 채팅 하나로 표지 한 장과 단락 그림 한두 장을 만들고,
  화면 안에서 1600px JPEG 로 줄여 받아 파일(`directus_files`, 행위자 `autopost@system`)로 저장한 뒤 본문 맨 위에 넣는다.
  그림 실패는 글을 막지 않는다. **그림의 내용은 아무 검사도 보지 않는다** — 지시문에 「글자·로고·상표·실존 인물 없음」을
  적은 것이 전부고, 사람 검수가 없으므로 어긋난 그림도 그대로 공개된다. 그림 파일은 만든 기계의 업로드 폴더에 놓인다 —
  사람 기계에서 만든 글을 운영으로 보내는 길을 정할 때 **파일도 같이 가야 한다**(DB 행만 보내면 운영 화면에서 그림이 깨진다).
- **글의 틀을 줄이고 강조 자리를 정했다(2026-11-13 사용자 요청)**: 맨 위 「핵심만 먼저」 세 줄, 단락의 첫 문단(결론)만 굵게,
  번호 단락 3~4개. 글 끝 고정 문구는 「AX(AI 전환) 도입을 고민 중이시라면?」으로 바꿨다 — 회사 이름이 드는 유일한 자리이고
  코드에 적힌 글자다. 대가: 결론 문장은 사실보다 판단에 가깝다 — 판정은 「출처가 말한 범위 안」인지만 보므로 과한 결론이 굵게 나갈 수 있다.
- **글 화면을 디자인했다(2026-11-13, 목업 승인 뒤 옮김)**: 큰 숫자 줄 · 3줄 요약 면 · 번호 머리글과 굵은 결론 · 어두운 문의 띠.
  본문 소독이 `dv_ap_` 로 시작하는 표시(class)를 남기도록 한 곳 넓혔다 — 모양은 `web/public/css/style.css` 가 그 이름에만 준다.
  관리 화면의 편집기는 이 표시를 모른다: 자동 글을 편집기로 열어 저장하면 꾸밈이 사라질 수 있다(확인 안 함).
  주제는 해외 현장 사례를 먼저 고르게 했다. 대가: 14일 안의 해외 1차 출처가 영어라 번역 오류가 판정에 더 기댄다.
