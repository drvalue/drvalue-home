# 0004 · 옛 주소는 308 로 넘기되 두 경로만 `.php` 를 유지한다

## 왜 정해야 했나

주소에서 `.php` 를 뺐다. 검색에 쌓인 옛 주소를 어떻게 할지, 그리고 바깥에
등록된 주소는 어떻게 할지를 정해야 했다.

## 무엇을 골랐나

옛 주소는 전부 **308** 로 새 주소에 넘긴다. 다만
`page/support/notice_api.php` 와 `page/support/notice_login_callback.php`
**두 경로만 옛 주소 그대로 산다.**

## 안 고른 것

- **전부 새 주소로 바꾸고 옛 주소는 버린다** — 검색에 쌓인 것을 잃는다.
- **두 경로도 새 주소로 옮긴다** — 콜백 주소가 IAM 화이트리스트에 글자
  그대로 등록돼 있다. 바꾸면 IAM 쪽 재등록이 필요하고, 그건 우리 손이
  아니다.
- **307(임시)** — 검색엔진이 옛 주소를 계속 색인한다. `.php` 주소는 다시
  살릴 계획이 없으므로 굳혀도 된다. 대신 **아직 확정이 아닌 주소 일곱**은
  일부러 307 로 뒀다(`dvRoutes.mjs`) — 같은 판단을 반대로 적용한 것이다.

## 그래서 생긴 제약

- Nest 인데 경로 두 개가 `.php` 다(`setGlobalPrefix` 의 예외 목록).
  새 경로를 만들 때 이 예외를 건드리지 않도록 주의해야 한다.
- 원본 대조 검사가 옛 주소로 양쪽을 부르는데, 파이썬 3.9 의 `urllib` 이
  308 을 안 따라가서 따라가도록 덧씌워 둬야 했다.
