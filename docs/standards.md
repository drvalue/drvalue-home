# 규칙


## 브랜치와 커밋

- **`main` 을 고치지 않는다.** 운영 배포가 이 저장소에서 나가므로 `main`
  에 들어간 것은 다음 배포에 그대로 서버로 간다.
- 작업은 `heysep/<주제>` 가지에서 한다.
- 커밋 메시지는 한국어로, **무엇을 왜** 를 적는다. 검사 숫자가 있으면
  제목에 넣는다(예: `(스모크 109/109)`). 같은 작업에서 고친 자기 실수도
  본문에 적는다 — 다음 사람이 같은 함정을 다시 밟는다.
- 평범한 `git push` 는 되돌릴 수 없는 행동이 아니다. 커밋으로 끝내지 않는다.

## 배포

- 운영 배포는 GitHub Actions 의 `Deploy (SSH)` 를 **사람이 수동 실행**한다.
  저장소 전체를 웹 루트로 `rsync` 한다.
- `rsync` 에 `--delete` 가 없다. **저장소에서 파일을 지워도 서버에서는 안
  지워진다.** 서버 파일을 없애려면 서버에서 직접 지운다.

## 자격증명

- `.env` 는 루트에 하나다. 저장소에 넣지 않는다. `.env.example` 을 복사해서 채운다.
- 토큰·비밀번호·해시를 출력·로그·문서에 그대로 쓰지 않는다.
- 새 비밀값이 필요하면 환경변수로 받는다. 기본값을 코드에 박지 않는다.
- **IAM 을 안 거치는 관리자 문을 만들지 않는다.** 토큰·헤더 우회 경로 금지. 검사는
  `ADMIN_SESSION_SECRET` 으로 같은 모양의 세션을 만든다.
- 환경변수는 `.env.example` 의 일곱 개뿐이다. 새로 만들기 전에 코드 상수나 compose
  배선으로 되는지 먼저 본다. api 에서 읽는 곳은 `common/config/app-config.ts` 하나다.

걸려 판정 불가로 빠진다. 통과도 실패도 아니다.

## 화면을 고칠 때

- **가로 스크롤이 생기면 안 된다.** 390 · 768 · 1024 · 1280 · 1440 에서
  확인한다. 표·도식·코드 블록만 예외이고, 그때도 자기 컨테이너 안에서만
  민다.
- **자바스크립트가 꺼진 사람에게 글이 사라지면 안 된다.** 스크롤 등장
  효과는 「보이는 것이 기본」으로 만든다 — 숨기는 일은 스크립트가 하고,
  스크립트가 안 돌면 전부 보인다.
- `prefers-reduced-motion` 을 켠 사람에게는 움직임을 끈다. 끄되 결과는
  같아야 한다(숫자는 최종값, 글은 보임).
- 손가락으로 누르는 기기에서 누를 것은 44px 이상이다. `@media (pointer:
  coarse)` 안에서만 키운다 — 마우스 화면까지 키우면 여백이 무너진다.
- `<img>` 에 `width`·`height` 를 적는다. 안 적으면 그림이 늦게 올 때
  브라우저가 높이를 0 으로 잡아 화면이 한 번 흔들린다.
- `transition: all` 을 쓰지 않는다. 속성을 나열한다.

## 사용자에게 보이는 문구

- 화면에 뜨는 말은 **합니다체이고 마침표로 끝낸다.** 공개 화면 · 관리 화면 · api 가 보내는
  에러 `message` · DTO 검증 문구 · 되돌리기 경고 전부다. 명사형 꼬리표(「저장됨」 「비어 있음」)는
  문장이 아니라 그대로 둔다.
- 주석 · 문서 · 로그는 한다체다. 둘을 섞지 않는다.
- 문구에 내부 용어를 쓰지 않는다. 환경변수 · 칸 이름 · 플래그(`force=1`) · 테이블 이름은 에러
  코드의 `detail`(개발자용, 응답에 안 실린다)에 적는다.
- 확인 버튼에는 「예/아니오」 대신 하는 일을 적는다(「지우기」·「되돌리기」 / 「취소」).
- 한국어는 낱말 사이에서만 줄을 바꾼다(`word-break: keep-all`).
- `check-copy.py` 는 반말 어미만 잡는다. 말이 어색하거나 내부 용어가 섞인 것은 사람이 읽는다.

## 페이지 CSS 문자열

페이지 전용 CSS 는 템플릿 문자열(`` ` ``)로 들고 있다. **그 안에 역따옴표를
하나라도 넣으면** 문자열이 거기서 끊겨 페이지가 통째로 문법 오류가 된다 —
모든 페이지가 500 이 되고 진짜 원인이 안 보인다. 주석에도 쓰지 않는다.
`check-src.py` 가 이것만 본다.

## 자료는 한 곳에서 읽는다

메뉴·제품 설명·과제 목록처럼 여러 화면이 쓰는 것은 **파일 하나**를 읽는다.
두 군데에 적어 두면 한쪽만 고쳐져 어긋난다.

- 상단 메뉴·현재 위치 줄·옆 차례표·사이트맵: `web/lib/menu.ts`
- 제품 기능·화면 캡처 설명: `web/app/page/business/max/maxContent.ts`,
  `web/app/page/service/solutionContent.ts`
- 수행 과제: `web/app/page/portfolio/portfolio/list.ts`

## 모듈 경계

- `web` 은 DB 를 직접 부르지 않는다. `/api` 만 부른다. 관리 화면(`/admin`)도 같다.
- DB 는 `api` 만 부른다. 테이블 이름은 옛 관리 도구 시절 것 그대로다 — 바꾸는 것은 마이그레이션이다.
- 루트의 PHP 파일에 **새 기능을 넣지 않는다.** 전환을 한 번에 하기로 했으므로
  PHP 쪽에 새 메뉴·새 화면을 넣으면 전환 전까지 두 곳을 다 고쳐야 한다.
