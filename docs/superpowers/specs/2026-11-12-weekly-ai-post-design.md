# 제조 AI 주간 글 자동 발행 — 설계

2026-11-12. 가지 `heysep/weekly-ai-post`.

## 무엇을, 왜

주 1회, 그 주의 제조 AI 소식 한 건을 골라 풀어 쓴 글이 뉴스 게시판
(`/page/support/news`)에 사람 손 없이 올라간다. 목적은 검색 유입을 문의로
잇는 것이다(목적은 작성자의 추측 — 사용자가 말로 확인한 것은 아니다).

기준으로 삼은 글은 Threads `@choi.openai` 의 형식이다. 그 계정이 AI 전반을
다룬다면 여기는 제조 AI 로 좁힌다. 같은 사용자의 다른 서비스(fitbory)가 이미
「조사 → 집필 → 검사 → 저장」 구조로 글을 만들고 있고, 이 설계는 그 순서를
가져온다.

## 사용자가 정한 것

- 주기는 **주 1회**.
- 소재는 **국내·해외 제조 AI** 소식.
- 글은 **choi 형식** — 훅, 번호 단락, 출처.
- **사람 검수·승인 없이 공개한다.** 자동 검사를 통과하면 누르는 것 없이 바로
  공개된다.

아래 나머지는 전부 작성자의 결정이다. 「결정」 표시가 붙은 것은 사용자가
듣고 반대하지 않았을 뿐 고른 것이 아니다.

## 목표 · 비목표 · 하면 안 되는 것

목표
- 한 주에 글이 최대 한 편, 검사를 통과한 것만 공개된다.
- 본문의 모든 수치는 본문에 링크된 출처 원문에서 확인된 것이다.
- 통과하지 못한 주는 건너뛴다. 억지로 내보내지 않는다.

비목표
- 검수 화면·알림(디스코드 등)·승인 버튼. 만들지 않는다.
- 영어 글. 한국어(`ko-KR`)만 쓴다.
- 그림. 본문에 그림을 넣지 않는다(출처의 그림을 가져오지 않는다).
- 여러 소식을 묶은 주간 요약. 한 편은 한 건만 다룬다.
- 공지·보도 게시판에 쓰기. 뉴스에만 쓴다.

하면 안 되는 것 (돌아가도 실패)
- 출처에 없는 수치·발표·인용이 회사 이름으로 실린다.
- 디알밸류의 제품 성능, 고객사, 실적에 대해 모델이 문장을 지어 쓴다
  (`docs/business-rules.md` 「화면에 쓰는 글은 지어내지 않는다」).
- 바깥에서 글을 쓸 수 있는 인증 길이 새로 열린다.
- 설정이 빠졌을 때 켜진 쪽으로 기운다.
- 게시판 글이나 문의 접수가 이 작업 때문에 깨진다.

## 어디서 도나

api(Nest) 안에 새 모듈 `autopost` 를 둔다. 이미 `admin-schedule` 이
`@nestjs/schedule` 로 매분 도는 자리 옆이다.

- **서버 안에서 저장한다.** 바깥 HTTP 입구를 만들지 않는다. 그래서 서비스
  토큰·API 키 인증이 필요 없다. 새로 생기는 비밀값은 Claude API 키 하나다.
- **글 저장은 `AdminPostDefaultService` 를 거친다.** 저장소에 직접 넣으면
  변경 이력(revision)·IndexNow·본문 소독·slug 겹침 검사가 빠진다.
  `create()` 는 지금 세션 정보(`SessionPayload`)를 받아 게시판 권한을 본다.
  관리자 세션을 흉내 내지 말고, 시스템 행위자용 입구를 좁게 하나 낸다 —
  행위자 이름 `autopost@system`, 쓸 수 있는 게시판은 `news` 뿐. 모양은
  만드는 사람이 정한다(`admin-schedule` 의 `schedule@system` 을 따른다).

## 언제 도나

정해진 시각에 한 번 쏘지 않는다. 배포는 사람이 서버에서 직접 하고, 그 순간
컨테이너가 내려가 있으면 그 주를 통째로 놓친다.

- 한 시간마다 「이번 주(ISO 주, KST) 기록이 있나」를 본다. 운영 컨테이너에는
  `TZ` 설정이 없으므로(`docker-compose.dev.yml` 에만 있다) 주와 시각은 코드에서
  +09:00 으로 명시해 계산한다. 화요일 09:00 KST
  이후이고 기록이 없으면 만든다(요일·시각은 결정).
- 주 단위 기록 표 `autopost_runs` 를 새로 둔다. 주 키에 unique 를 걸어 두
  프로세스가 같은 주를 동시에 잡지 못하게 한다. 칸: 주 키, 상태(진행 중 ·
  공개 · 초안으로 남김 · 건너뜀 · 오류), 사유, 글 id, 시도 횟수, 쓴 토큰 수,
  시각.
- 한 주에 시도는 최대 2번. 오류(API 실패 등)로 끝난 주만 다음 시간에 한 번
  더 한다. 검사 탈락으로 끝난 주는 다시 하지 않는다 — 돈이 드는 호출이라
  무한히 되풀이하지 않는다.
- 「진행 중」이 2시간 넘게 남아 있으면 죽은 것으로 보고 오류로 닫는다.
- 조사·집필은 몇 분이 걸린다. **그동안 DB 트랜잭션을 잡지 않는다.**
  트랜잭션은 기록 행을 잡을 때와 글을 저장할 때만 짧게 연다.

## 한 편이 만들어지는 순서

Claude API(`@anthropic-ai/sdk`)를 쓴다. 모델 `claude-opus-5-5`, 웹 검색
`web_search_20260209`, 웹 fetch `web_fetch_20260209`, 구조화 출력은
`output_config.format`(2026-11-03 기준 스킬 자료로 확인. 구현할 때 SDK 문서로
다시 확인한다). 거절 응답(`stop_reason: "refusal"`)은 오류로 다룬다.

1. **조사.** 웹 검색으로 최근 14일 안의 제조 AI 소식을 찾아 한 건을 고른다.
   범위: 공장·생산·품질 검사·설비 예지보전·공정 최적화·산업용 로봇·제조
   현장의 AI 도입 사례·관련 정책과 지원 사업. 소비자용 AI 제품 소식은 뺀다.
   이미 낸 글(최근 자동 글의 제목과 출처 주소)을 같이 주고 겹치지 않게 한다.
   1차 출처(발표한 회사·기관의 글, 논문)를 우선한다.
2. **집필.** 구조화 출력으로 받는다. HTML 을 모델이 쓰지 않는다.
   - 제목, 요약, 검색용 설명
   - 훅 단락(핵심 수치 두세 개)
   - 번호 단락 4~6개. 단락마다 한 가지: 무엇이 나왔나 → 핵심 수치 → 이전·
     경쟁과의 차이 → 현장에서의 쓰임새
   - 출처 목록: 제목·주소·발행처·발행일
   - 주장 목록: 본문에 쓴 수치·인용 하나마다 「문장 · 값 · 출처 주소 · 출처
     원문의 해당 구절」
   말투는 「~습니다 / ~인데요」 존댓말, 문단은 한두 문장, 어려운 개념은 일상
   비유로 한 번 푼다. 이모지와 「🧵」 같은 Threads 표시는 쓰지 않는다(결정 —
   회사 사이트 글이다).
3. **검사.** 아래 「검사」.
4. **다시 쓰기.** 떨어지면 떨어진 사유를 붙여 **한 번만** 다시 쓰고 다시
   검사한다.
5. **저장.** 통과하면 공개로 저장한다. 두 번째도 떨어지면 **글을 만들지
   않는다** — 사유와 떨어진 글의 구조화 출력을 `autopost_runs` 에만 남긴다
   (결정). 사실 확인에 떨어진 글이 관리 화면 뉴스 목록에 일반 초안처럼 놓이면
   누르는 것 한 번으로 공개된다. 볼 사람이 정해져 있지 않은 초안은 두지
   않는다.

## 검사

코드가 하는 것(모델 판단 없음)
- 구조: 제목 길이, 단락 개수, 출처 1개 이상, 주소가 http(s).
- 출처 발행일이 14일 안이다.
- 출처 주소가 이미 낸 자동 글의 출처와 겹치지 않는다.
- **본문에서 숫자를 전부 뽑아, 각각이 「확인됨」 판정을 받은 주장에
  들어 있는지 본다.** 주장 목록에 없는 숫자가 본문에 있으면 떨어진다
  (날짜·번호 단락의 번호처럼 미리 정한 예외만 통과).
- 금지 문자열: 「디알밸류」·제품 이름(`GrowXD`·`CosmoGMP`·`M.AX`)이 모델이 쓴
  칸에 나오면 떨어진다. 예외 하나 — 「M.AX 얼라이언스」(산업부의 제조 AX
  얼라이언스, 2025-09 출범)는 통과시킨다(결정). 자사 제품과 이름이 같은 정부
  사업이고, 막으면 국내 정책 소식이 매번 그 주를 건너뛴다. 출처 제목 칸은 이
  검사를 받지 않는다(바깥 글의 제목을 그대로 적는 칸이다).
- 만든 HTML 이 `sanitizeBody` 를 지나도 한 글자도 안 바뀐다.

별도 호출이 하는 것
- 글을 쓴 호출과 **다른 호출**이 출처 주소를 웹 fetch 로 다시 읽고, 주장
  하나마다 「출처 원문에 그 값이 그 뜻으로 있다 / 없다」를 판정한다. 하나라도
  「없다」면 떨어진다. 출처가 안 열리면 그 출처에 기댄 주장은 전부 「없다」다.
- fetch 는 Anthropic 쪽에서 돈다. **api 컨테이너가 모델이 고른 주소를 직접
  열지 않는다**(서버가 임의 주소를 여는 면을 만들지 않는다).

검사가 못 막는 것 (산출물에도 적는다)
- 출처 자체가 틀렸거나 과장된 보도자료일 때.
- 수치는 맞는데 해석·전망이 과한 문장.
- 판정 호출이 틀리게 「있다」고 한 경우. 숫자 대조는 코드가 하지만 「그 뜻으로
  쓰였나」는 모델 판단이다.
- 소재 선택의 질(중요하지 않은 소식을 고르는 것).

## 글의 모양

코드가 구조화 출력을 HTML 로 바꾼다. 쓰는 태그는 `sanitizeBody` 가 받는
것만: `p`, `h2`, `strong`, `ol`/`ul`/`li`, `a`.

```
<p>훅 단락…</p>
<h2>1. 무엇이 나왔나</h2>
<p>…</p>
…
<h2>출처</h2>
<ul><li><a href="…" target="_blank" rel="noopener noreferrer">제목</a> — 발행처, 2026-11-10</li></ul>
<p>(고정 문구 — 아래)</p>
```

- 게시판 `news`, 언어 `ko-KR`, `seo_title`·`seo_description` 채움.
- `published_date` 는 **공개한 날(KST)**. 문서는 「사람이 정한 날짜」라고
  적고 있으므로 문서를 고친다(아래).
- slug 는 `mfg-ai-<YYYYMMDD>` 꼴(결정). 겹치면 저장이 거부되고 그 주는 오류.
- 그림 없음. 뉴스 게시판의 대표 그림은 본문 첫 그림이라 대표 그림도 없다.
  상세는 기본 그림으로 대체한다(`BoardArticle.tsx`). **목록(`BoardList.tsx`)과
  첫 화면 소식 칸(`HomeNews.tsx`)이 그림 없는 글에서 깨지지 않는지 구현할 때
  확인한다.**
- 글 끝 고정 문구는 **코드에 적힌 글자**이고 모델이 쓰지 않는다(아래
  「사용자가 답한 것」).

## 닫힌 기본값

- 환경변수 `AUTOPOST_ENABLED`(켜기)와 `ANTHROPIC_API_KEY` 둘 다 있어야 돈다.
  하나라도 없으면 아무것도 안 하고, 시작할 때 꺼져 있다고 한 줄 남긴다.
- API 오류·시간 초과·거절·형식 오류는 전부 「공개 안 함」으로 끝난다.
- 키 값은 로그·기록 표·오류 문장에 싣지 않는다.
- 「초안으로 남김」 상태는 손으로 돌린 것에만 쓴다. 자동 실행은 공개 아니면
  건너뜀이다.
- 실패는 서버 로그와 `autopost_runs` 에만 남는다. **알림은 없다**(결정 —
  사용자가 알림 방식을 정하지 않았다). 몇 주째 건너뛰어도 누가 표나 로그를
  보기 전에는 모른다.

## 손으로 돌리기

api 에 명령 하나를 둔다(이름은 만드는 사람이 정한다).
- 보기만: 한 편을 만들어 검사 결과·HTML·쓴 토큰 수를 출력하고 저장하지
  않는다.
- 초안으로: 같은 일을 하고 초안으로 저장한다(공개하지 않는다).

첫 운영 전에 「보기만」으로 몇 편을 만들어 사용자가 읽어 본다. 한 편당 비용은
**NA(아직 못 쟀다)** — 이 실행의 토큰 수로 잰다.

## 완료의 증거

- 검사 규칙 테스트: 고정 자료로 「주장에 없는 숫자」「금지 문자열」「오래된
  출처」「겹치는 출처」가 각각 떨어지는 것.
- 만든 HTML 이 `sanitizeBody` 의 고정점인 것.
- 같은 주에 두 번 불러도 글이 한 편인 것. 환경변수가 없으면 Claude 를 한
  번도 부르지 않는 것.
- 「보기만」 실행 한 번의 실제 출력(글·검사 결과·토큰 수).
- 「초안으로」 실행 뒤 그 글이 공개 목록·sitemap·RSS 에 **안** 나오는 것,
  공개로 바꾸면 나오는 것.
- 기존 검사(`docs/standards.md` 「검사 통과 기준」, `check-boards.py`)가 줄지
  않고 통과하는 것.

## 만드는 사람에게 남긴 것

- 시스템 행위자 입구의 모양, 모듈 안 파일 나눔, 표의 정확한 칸 이름과
  마이그레이션.
- 프롬프트 문장. 단 위의 범위·말투·금지 사항은 지킨다.
- 숫자 뽑기 규칙의 예외 목록.
- Claude 호출의 `effort`·`max_tokens`·시간 제한 값.

## 사용자가 답한 것 (2026-11-12)

- **AI 작성 표기는 넣지 않는다.**
- **글 끝에 문의로 잇는 고정 문구를 넣는다.** 문의 페이지
  (`/page/support/notify_form`) 링크가 든 한 문단이고, 코드에 적힌 글자다.
  모델이 쓰지 않는다. 문구에는 제품 성능·고객사·수치를 넣지 않는다.
- **`docs/security.md` 는 코드에서 다시 만든다.** 원본 사본이 없어 사용자가
  그렇게 정했다. 다시 만든 문서에는 원본에만 적혀 있던 열린 문제가 없다.
