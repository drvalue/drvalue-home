# 알아 두지 않으면 걸리는 것들

## 캐시가 안 깨져서 CSS 고친 게 안 보인다

**증상** — CSS 를 고쳤는데 화면이 그대로다.
**원인** — `header.php` 의 `asset_url()` 은 파일 수정시각을 주소에 붙여
캐시를 깼다. Next 쪽에는 그게 없다.
**대응** — 브라우저 캐시를 무시하고 새로고침해서 먼저 구분한다.

## 파이썬 3.9 의 urllib 은 308 을 안 따라간다

**증상** — 옛 주소로 부르면 Next 쪽 응답이 308 본문 그대로다.
**원인** — `urllib` 이 308 을 리다이렉트로 취급하지 않는다.
**대응** — `web/scripts/compare.py` 가 `redirect_request` 를 덧씌워 둔다.
새 파이썬 스크립트를 만들 때 같은 처리가 필요하다.

## TypeORM 의 synchronize 는 엔티티에 없는 칸을 지운다

**증상** — 부팅 뒤 테이블에서 칸이 사라진다.
**원인** — 테이블은 옛 관리 도구가 만든 것이고 엔티티는 그중 쓰는 칸만 적었다.
`synchronize: true` 는 그 차이를 「지워야 할 칸」으로 본다.
**대응** — 절대 켜지 않는다(`common/database`). 스키마 변경은 `db/schema.sql` 과 마이그레이션.

## 관리 화면 로그인이 `bad state` 로 막힌다

**증상** — IAM 에서 돌아오자마자 403 `ADMIN_AUTH_BAD_STATE`.
**원인** — 화면을 연 주소와 콜백 주소의 호스트가 다르면(`127.0.0.1` 대 `localhost`)
state 쿠키가 못 따라온다. IAM 이 `state` 를 되돌려주지 않는 경우도 있다.
**대응** — state 를 서명값으로 쿠키와 쿼리 양쪽에 싣고 둘 중 하나만 맞으면 통과.
`ADMIN_IAM_CALLBACK_URL` 은 화면을 여는 그 주소로.

## Express 의 trust proxy 는 "1" 을 홉 수로 안 읽는다

**증상** — 프록시 뒤에서 IP 별 속도 제한이 하나로 합쳐진다.
**원인** — `.env` 값은 항상 문자열인데, Express 는 `"1"` 을 홉 수가 아니라
IP `0.0.0.1` 하나를 믿는 목록으로 읽는다. 결과적으로 아무것도 안 믿는다.
**대응** — Nest 쪽에서 숫자로 바꿔 넘긴다(`trustProxyValue`). 돌연변이로
확인했다 — 바꾸지 않으면 검사가 잡는다.

## 속도 제한이 프로세스 메모리에 있다

**증상** — 컨테이너를 둘 이상 띄우면 IP 당 한도가 프로세스당 한도가 된다.
**원인** — PHP 는 파일로 워커끼리 공유했지만 Nest 는 프로세스 메모리다.
**대응** — 컨테이너 한 개 전제다. 늘리는 순간 Redis 저장소로 바꿔야 한다.

## `backdrop-filter` 가 걸린 조상 밑에서 `position: fixed` 가 갇힌다

**증상** — 메뉴판 뒤를 덮는 어두운 막이 헤더 높이(80px) 안에 갇힌다.
**원인** — 조상에 `backdrop-filter` 가 있으면 `fixed` 의 기준이 뷰포트가
아니라 그 조상이 된다.
**대응** — `position: absolute` + `top: 100%` + `height: 100vh` 로 푼다.

## 판이 여럿이면 닫힘에도 페이드를 주면 안 된다

**증상** — 탭을 옮길 때 두 메뉴판의 글자가 겹쳐 읽힌다(실측: 40ms 지점에
투명도 0.70 과 0.29 가 동시에 보였다).
**원인** — 탭마다 판이 따로 있고 전부 같은 자리에 뜬다.
**대응** — 닫힘은 `transition: opacity 0s` 로 즉시, 열림만 페이드.

## flex 자식은 안 늘어난다

**증상** — 히어로 글이 가운데로 밀렸다(왼쪽 여백이 100px 이어야 하는데
410px). 탭 밑줄 길이가 탭마다 달랐다(53·35·54·53·40·53px).
**원인** — `display:flex` 안의 자식은 내용 폭으로 줄어든다. `margin: 0 auto`
는 그 줄어든 덩어리를 가운데로 보낸다.
**대응** — `width: 100%` 또는 `flex: 1` 을 준다.

## grid 의 `align-items: start` 가 sticky 를 죽인다

**증상** — 옆 차례표가 스크롤을 따라 올라가 화면 밖으로 나간다(top 이
−1190 까지 갔다).
**원인** — 격자 칸이 제 내용 높이로 줄어들어 `position: sticky` 가 붙어
있을 자리가 없어진다.
**대응** — 기본값 `stretch` 로 둔다.

## `auto-fit` 이 안 쓰는 칸을 0px 로 하나 더 만든다

**증상** — `grid-template-columns` 가 `405 405 405 0px` 로 나온다.
**원인** — `repeat(auto-fit, minmax(...))` 가 빈 칸을 0 으로 접는다.
**대응** — 칸 수가 정해져 있으면 `repeat(N, 1fr)` 로 박는다. 다섯 칸을
넣을 때 `minmax(0, 268px)` 는 1280px 안에 넷만 들어가 다섯째가 혼자
내려간다 — 250px 이면 다섯이 들어간다.

## 나중에 오는 줄임 표기가 앞의 한 방향 값을 지운다

**증상** — 칸 안쪽 여백을 줬는데 글머리 점이 테두리에 붙어 있다.
**원인** — 앞에서 `margin-left: 22px` 를 주고 뒤에서 `margin: 12px 0 0` 을
주면 좌우가 0 이 된다. 명시도가 같으면 뒤가 이긴다.
**대응** — 안쪽 여백은 부모의 `padding` 으로 주고, 밖으로 빼낼 것만 음수
`margin` 을 준다.

## `:has()` 로 쓴 규칙은 통째로 죽는다

`:has()` 를 못 쓰는 브라우저에서는 그 규칙 전체가 무시된다. 그래서
**기본 상태가 안전한 쪽이어야 한다.** 헤더 투명 규칙이 죽으면 흰 막대로
남는 것이 안전한 실패다.

## 서버가 그린 화면과 스크립트가 켜는 상태가 다르면 번쩍인다

**증상** — 어두운 머리 그림이 있는 장을 열 때마다 흰 막대가 한 번 보였다
사라진다. 정지 화면 캡처로는 안 잡힌다.
**원인** — 서버는 흰 막대를 그리고 스크립트가 붙은 뒤에 투명으로 바꿨다.
**대응** — 조건을 CSS 안에 넣어 서버가 그린 화면부터 최종 상태가 되게
한다. 스크립트는 「내렸을 때 표시를 붙이는」 일만 한다.

## 숨겨 놓고 스크립트가 켜는 구조는 스크립트가 죽으면 글이 사라진다

이 저장소에 실제로 그 덫이 있었다 — `style.css` 의 `.reveal` 은
`opacity: 0` 인데 `.active` 를 붙이는 코드가 **한 곳도 없었다**. 누가
`class="reveal"` 을 붙이는 순간 그 글은 영원히 안 보인다.
**대응** — 숨기는 일을 스크립트가 한다. 접힌 선 아래 것만 숨기고(첫 화면은
건드리지 않아 번쩍임이 없다), 관찰이 안 돌면 몇 초 뒤 전부 켠다.

## 작은 원본을 올려 키우면 흐려진다

**증상** — 502×721 그림이 700×1005 로 늘어나 뭉갠다.
**대응** — `style={{ maxWidth: 원본폭 }}` 으로 상한을 준다.

## RSC 응답은 같은 주소를 두 번 담는다

Next 는 서버 컴포넌트 결과를 HTML 안에 한 번 더 문자열로 넣는다. 응답에서
`grep -o` 로 주소를 세면 **한 번 쓴 것이 두 번 세어진다.**

## 정규식으로 태그 덩어리를 자를 때

`<li> ... 그 주소 ... </li>` 같은 규칙은 본문 어디에 그 주소가 있어도
한참 앞의 여는 태그부터 한참 뒤의 닫는 태그까지 먹는다. 실제로 홈에 링크를
둘 더 놓았더니 45,000자가 사라졌고 그 안에 `</head>` 가 있었다 — 그 뒤로
검사기가 본문을 통째로 `<head>` 로 세서 검사 세 개가 깨졌다.
**대응** — 주소만 보지 말고 「메뉴 안이라는 것」까지 확인한다.

## 도커가 안 뜰 때

원본 대조(`compare-all.sh`)는 로컬 PHP(:3300)를 쓴다. 도커가 멈췄으면
`PHP_ORIGIN=https://drvalue.co.kr` 로 운영본을 원본 삼아 돌린다. 읽기만 한다.
`check-home.py` 는 원본을 더 안 부른다 — 대신 Nest(:3500)가 떠 있어야 한다.

## 검사 순서

`check-src.py` 를 먼저 돌린다. 페이지 CSS 문자열이 깨져 있으면 모든
페이지가 500 이 되어 「전부 다름」으로 나오고 진짜 원인이 안 보인다(두 번 겪었다).

## 페이지를 다시 옮기면 무거운 그림이 되살아난다

원본 PHP 는 `/img/main_bg_01.jpg` 같은 주소를 그대로 쓴다. 그 파일은
1.3MB 이고, 줄인 판이 `/opt/` 에 180KB 로 있다. 손으로 `/opt/` 로 바꿔 놔도
그 페이지를 다시 옮기면 원본 주소가 돌아온다.

**아무 검사도 이걸 안 잡는다.** 자산 검사는 파일이 있는지만 보고, 원본
대조는 두 주소를 같은 그림으로 세도록 돼 있다. 그래서 `port.py` 가 쓰기
직전에 기계로 바꾼다 — 손으로 고치는 자리가 아니다.
